向いている使い方

板一覧、お気に入り、画像ギャラリー、抽出レス、スレプロパティ、将来の書き込み画面を上端のアイコンから切り替える。モック内のアイコンを押すと表示が切り替わる。

トレードオフ

パネル幅を増やさず複数のビューを切り替えられる一方、アイコンだけでは意味が分かりにくいため、ツールチップや選択中の表示が必要。

操作の提案

上端のアイコンを押すと、そのビューに切り替わる。選択中のビュー名は下の見出しに表示。右上の × はパネル全体を閉じ、再表示時は最後のビューを復元する。

状態の提案

抽出レスは入力中に即時絞り込み、空欄なら結果を表示しない。検索条件とスクロール位置はビューごとに保持。追従中は親のスレッド変更に合わせて内容を切り替え、スレッドごとの状態を分けて保存する。取得済みデータは親画面と共有する。

共通仕様のたたき台

まずは A を基準にした提案です。画像一覧は将来の例であり、#198 の初期実装に必須とは限りません。

開く・切り替えるツールバーからパネルを開き、見出しの選択メニューでビューを切り替える。閉じると本文はそのまま。幅はドラッグで変更し、次回も復元。
追従先アクティブなペインの選択中タブに追従。２ペインでは対象を見出しに表示し、アクティブペインが変われば切り替える。スレ以外では「スレッドを開くと表示されます」。
固定追従を解除して特定スレッドに固定できる案。固定中は対象名を表示し、親タブを閉じても対象を保持する。初期版に入れるかは要検討。
更新・選択取得済みのスレデータと更新結果を共有。パネル内の項目選択は本文の該当レスへ移動するが、スクロール位置や選択状態は別々に保持。自動更新の開始・停止は親側が管理。
空・エラー対象なし、該当項目なし、読み込み中、取得失敗を区別。失敗時は理由と再試行を表示し、可能なら前回取得分を残す。
狭い画面本文の最小幅を下回る場合はパネルを重ねて表示し、閉じる操作を常に確保。２ペイン時も同様に扱う。
通常ペインとの違いサブレンズは補助的な閲覧・抽出に絞り、通常のタブ履歴や独立したナビゲーションを持たない。常時並べて別スレを読む用途は通常ペインへ。
対応環境まず Tauri・Chrome・Firefox で同じアプリ内 UI として検討。ブラウザ固有のサイドパネル API に依存するかは別途判断。

決めたい点：右側と左側のどちらが自然か／最初に置きたいビューは何か／固定表示や２段表示が必要か。
