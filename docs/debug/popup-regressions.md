# ポップアップと実況・返信IDの回帰確認

## 自動更新の一時停止（#196）

2026-10-25、保存先を分離した実Tauri/WebView2で確認した。
修正前はライブチャット表示とコメントOverlayを有効にしてアンカーポップアップを
ピン留めしても、6.5秒間に新たなdat取得が2回発生した（更新間隔3秒）。
表示の一時停止を通信の開始条件へ渡していなかったため、取得だけは継続していた。

停止・再開条件は次のとおり。

- 「ポップアップ表示中は一時停止」がONで、表示中タブにポップアップが1つ以上ある間は、
  新しい自動取得・本文の追従・ライブチャットの新着表示を待機する。
- 子ポップアップだけ閉じても、親が残っていれば待機を続ける。ピン留めも同じ扱い。
- 開く前から進行中の取得は中断しない。取得結果を保存し、表示キューの再生は待機する。
  手動の更新操作は引き続き利用できる。
- 最後のポップアップを閉じるか設定をOFFにすると、通常の更新間隔を数え直して再開する。
  開閉のたびに即時取得しない。
- 別タブへ移ると、そのタブに残ったポップアップで非表示タブのOverlay実況を止めない。
  Overlay実況をしていない非表示タブは、従来の非アクティブ条件で取得を止める。
- タブの自動更新ON状態は保持する。OFF・dat落ち・停止記録による停止条件が優先する。
  新着なしによる自動停止の判定方式は変更しない。
- Overlayに既に配信したコメントの移動は止めない。

回帰テスト:

- [use-auto-refresh.test.tsx](../../src/features/auto-refresh/browser/use-auto-refresh.test.tsx):
  通常表示・ライブチャットでの待機と再開、取得中の開閉、OFF後の再開防止。
- [popup-auto-refresh.spec.mts](../../tests/tauri/popup-auto-refresh.spec.mts):
  実TauriでOverlay実況中の固定アンカーポップアップ、子ツリーの開閉、
  最後のポップアップを閉じた後の取得と表示、別タブに移った後の取得継続。

## 単一ポップアップ内の複数返信ID（#133）

- 返信ツリー・ID・アンカーポップアップそれぞれの表示対象を独立に集計する。
  アンカーポップアップは実際に表示する先頭8件、返信ツリーは描画と同じ深さ上限・
  循環・重複除外を適用する。未入場のライブチャット新着は含めない。
- 同じID（表記の完全一致）が同じレス番号へ、2件以上の異なるレスから返信した場合に、
  その返信レスのIDを太字・二重下線にする。返信先自身や、そのIDの無関係な投稿は強調しない。
- 同一レス内の重複アンカーを重複計上しない。範囲・分岐・全角アンカーと25件の上限は
  既存の返信索引に合わせる。IDなし・空IDは対象外。
- NG判定のあるレスは集計から除外する。NG全体を一時解除したときは集計へ含める。
  個別プレースホルダーを開いただけでは集計対象を変えない。
- スレッド本文の表示、ID全体の出現数・色、返信数の集計は変更しない。

集計の単体テストと返信ツリーの表示テストに加え、
[popup-repeated-reply.spec.mts](../../tests/tauri/popup-repeated-reply.spec.mts)で
実Tauriの返信ツリー・IDポップアップの強調、既存ID件数の保持、本文への非適用を確認する。
撮影した画面でも同一IDの別宛先の投稿と区別できることを確認した。
