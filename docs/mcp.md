# ChLens MCP

ChLensのChrome版に保存されているスレッドログを、MCP対応エージェントから読み取るための接続機能です。ChLensの画面を開いている間、MCPサーバーからの要求を既存のThreadServiceへ渡します。

## できること

- URLを指定したスレッドの取得
- URLを省略した現在表示中スレッドの取得
- 保存済みログの検索
- 未保存スレッドの新規取得と保存
- 先頭・末尾・レス番号範囲・人気レスによる絞り込み
- レスの返信先、被返信先、返信数、アンカー数を含むTOON出力

`read_thread` の `mode` は次の3種類です。

- `auto`: キャッシュを使い、必要なら通常の取得処理を行う（既定）
- `cache`: 保存済みログだけを使う。保存がなければエラーにする
- `refresh`: 新着を取得して保存してから返す

絞り込みを指定しない場合も、1回の応答は最大500レスに制限します。続きが必要な場合は `start` / `end` または `last` を指定してください。

## 起動

リポジトリのルートで次を実行します。

```text
pnpm mcp:server
```

MCPクライアントの設定例です。実際の設定ファイルの形式やキー名はクライアントに合わせてください。

```json
{
  "mcpServers": {
    "chlens": {
      "command": "pnpm",
      "args": ["mcp:server"],
      "cwd": "V:\\repos\\fork\\read.crx-2"
    }
  }
}
```

サーバーは標準入出力でMCPを受け付け、同時に `127.0.0.1:17890` でChrome版との一時的な中継を開きます。Chrome版ChLensのブラウザ画面を開いていれば、自動的に中継へ接続します。MCPサーバーを終了すると中継も終了するため、常駐プログラムの登録は必要ありません。

## 安全上の扱い

- 中継はループバックアドレスだけで待ち受けます。
- MCPサーバーが動いていない間、Chrome版は接続を指数バックオフで再試行します。
- レス本文はユーザーが要求した範囲だけを返します。
- 現在の実装では、MCPサーバーの標準エラーに診断情報を出し、標準出力にはMCPのJSON-RPCだけを書きます。

## 現在の制約

Chrome版ChLensの画面を閉じている場合は、Chrome側のログへ接続できません。MCPサーバーは起動したまま待機し、ChLensの画面が開くと再接続します。

Chrome版の拡張機能IDやNative Messagingの登録は使わないため、開発ビルドと通常インストールを切り替えるたびに登録し直す必要はありません。
