# 複数スレッドの過去実況再生計画

作成日: 2026-09-17

状態: 試作実装済み。ドメイン処理、Storybook試作、Tauri専用の独立操作窓、既存コメントOverlayへの再生通知、ThreadViewのレスメニューからのシーク要求、Mainの専用ThreadViewタブへの現在スレ同期を接続済み。保存・正式Issue運用・実機確認は未着手。

調査基準: ローカルの `develop`、`3b84d5ea`。リモートとの差分確認や取得は今回行っていない。
計画ブランチ: `docs/comment-overlay-archive-replay-plan`

## 1. 目的と利用場面

一人で録画・配信のアニメを見る際に、放送当時の実況コメントを重ねて、当時の視聴者と一緒に見ている感覚を得る。

利用者は対象番組の実況スレッドURLを複数、手動で入力する。例えばある日の23:30から翌00:00までの30分間を指定し、その時間に投稿されたレスを、スレッドをまたいで当時と同じ時間間隔で流す。

「前スレの全レスを流してから次スレを開始する」方式では、スレ移行中に重なった投稿時刻を再現できない。このため、入力された全スレッドのレスを投稿時刻順の一つのタイムラインに統合する。

## 2. 確定している要望と計画上の推奨案

### 利用者から確認できている要望

- 複数のスレッドURLを手動入力する。
- 指定した放送時間帯の実況を、動画視聴と並行して再生する。
- 放送中にスレッドをまたいでいても、自然にコメントがつながる。
- 将来は複数スレッドを一つのスレッドのように読む機能も検討する。
- 追加の機能案として、スレッド閲覧中に選んだレスの位置へ実況再生をスキップできるようにする。
- 計画作成時点では実装せず、専用ブランチに詳細な計画を残す。

### この計画の推奨案（利用者による最終決定前）

- 最初は既存Overlayと同じTauri版を対象とする。
- 日付・開始時刻・再生時間を指定する。再生時間の初期値は30分。
- 再生・一時停止、シーク、10秒移動、1秒単位の同期補正を備える。
- 操作UIは小さな専用ウィンドウとし、設定領域を折りたためるようにする。
- URL群と同期設定を保存し、再利用できるようにする。
- 初期版では外部動画の操作・自動同期を行わず、利用者が動画と実況を開始する。

## 3. 初期版の範囲

### 対象

- 複数URLの改行貼り付け、追加・削除、入力チェック、重複排除。
- 各スレッドの取得状況、取得エラー、対象レス数の表示。
- 放送日時と再生時間の指定、日付またぎ。
- 投稿時刻の解析、時間範囲の抽出、スレッド横断の安定した整列。
- 再生・一時停止・先頭へ戻る・シーク・秒移動・同期補正。
- スレッドのレスメニューから「この位置まで過去実況を再生」する操作。
- 既存Overlayの文字・画像・NG処理との接続。
- 混雑時にコメントの表示遅延が積み重ならない制御。
- 設定の保存・復元と、ライブ実況との排他的な切り替え。

### 後続で扱うもの

- 自動次スレ探索、URLの自動収集。
- 連結したスレッドの閲覧画面、通し番号表示。
- 動画プレイヤーとの連携、自動一時停止・自動シーク追従。
- CMカット区間の登録、区間ごとの同期ポイント、倍速再生。
- 複数の放送局・別放送回のログを時差補正して混ぜる機能。
- 再生設定の共有・エクスポート、ブラウザ版での同等機能。

## 4. 利用の流れと画面

1. Tauri版のコマンドパレットから「過去実況を再生」を選び、独立した操作窓を開く。
2. 設定領域へ複数URLをまとめて貼り付ける。
3. 必要なら放送日・開始時刻を指定し、再生時間を入力する（開始日時を空欄にすると取得ログの最初の投稿から開始する）。
4. 「読み込む」を押し、各URLの取得結果と対象レス数を確認する。
5. 動画を開始位置で待機させ、動画と実況を再生する。
6. 必要に応じて「コメントを早く／遅く」で同期を調整する。
7. 視聴を中断するときは実況も一時停止する。

### 展開時の操作例

```text
過去実況の再生

実況スレッドURL（1行に1件）
[                                             ]
[                                             ]

放送日 [2026/09/16] 開始 [23:30:00] 時間 [30分]
対象: 2026/09/16 23:30 ～ 2026/09/17 00:00（日本時間）
[読み込む]

スレッド① 取得済み / 対象420件
スレッド② 取得済み / 対象580件
スレッド③ 取得失敗 [再試行]

[▶ / ⏸] [先頭へ] 05:20 / 30:00 実況時刻 23:35:20
────────●────────────────────
[10秒戻す] [10秒進める]
コメントを [1秒早く] [1秒遅く] 補正: 0秒 [補正を戻す]

[設定を保存] [設定を折りたたむ]
```

### ウィンドウの役割

- 表示用Overlayは動画に重ねる描画面として維持する。
- 操作用ウィンドウ（Tauriの `archive-replay` window）に入力欄と再生ボタンを置く。透明Overlayのクリック透過と入力操作を混同しない。
- 操作用ウィンドウはコメントを描画せず、再生世代付きのイベントを `comment-overlay` window へ送る。動画上のコメント表示は常に既存Overlayが担当する。
- 操作用ウィンドウから「現在の実況スレをメインで開く」を実行できる。Main側では通常の閲覧タブを上書きせず、実況専用のThreadViewタブを作成して再利用する。
- 「メインを実況スレに追従」を有効にした場合だけ、再生時計がスレ境界を越えたときにセッションID・世代番号付きでMainの専用タブを切り替える。手動ボタンでは追従を有効にせず一度だけ開ける。
- 折りたたみ時も再生状態、経過時間、シーク、同期補正を操作できる。
- 最前面固定は切り替え可能にする案とする。複数モニターで位置を復元する場合は画面外配置を補正する。
- 初期案では操作ウィンドウを閉じたら再生を一時停止する。再度開くと位置を保持する。
- Overlayだけの非表示では時計を止めず、再表示時に現在位置を描画する。再生中／非表示をコントローラーに表示する。
- ThreadViewのレスメニューは、操作窓へスレURLと絶対レス番号を送り、操作窓側で投稿時刻から再生位置へ変換する。操作窓内にレス一覧を複製しない。

## 5. 日時とレスの取り扱い

### 時間範囲

- 初期版の指定日時は日本時間として明示し、OSのタイムゾーンに依存させない。
- 開始日時を絶対時刻に変換し、終了日時は開始日時＋再生時間から求める。
- 対象範囲は開始を含み終了を含まない半開区間とする。隣接する再生枠の境界で重複させないため。
- 23:30開始・30分の場合、翌00:00ちょうどの投稿は次の枠に属する。
- 日付、時刻、正の再生時間を検証し、不正値は取得前に表示する。
- 放送表記の24:00や25:00を入力可能にするかは後続判断とし、初期版は通常の日付と00〜23時を使う案とする。

### 投稿時刻の解析

- `IRes.date` は文字列であるため、既存日時処理の対応形式を調査し、掲示板ごとの書式を明示的に解析する。
- 実装依存の文字列日時解析に任せず、曜日・小数秒・タイムゾーン有無などを検証する。
- 解析できない投稿は時刻を推測して補完しない。再生対象から除外し、URLごとの件数と理由を表示・ログ記録する。
- 元の日時文字列も保持する。同じ秒に複数の投稿がある場合、架空の小数秒は生成しない。

### 整列と重複

- 第一キーは投稿時刻、同時刻の場合は入力スレッド順、次に元レス番号とする。
- レスの同一性は正規化したスレッド識別子と元レス番号で決める。
- 同じURLやレス指定付きの同一スレッドURLは、既存のURL正規化を通して重複を除く。
- 異なるスレッドの同文投稿は別のレスとして扱い、本文一致では除外しない。
- 無投稿の区間を詰めない。無投稿だけを根拠にログ不足と断定しない。
- 読み込み後は再生用スナップショットを固定し、再生中の追加取得で順序を変えない。

## 6. 再生時計と同期補正

### 基準となる計算

```text
投稿の相対時刻 = 投稿日時 − 放送開始日時
コメントの予定表示時刻 = 投稿の相対時刻 ＋ 同期補正
```

同期補正の正値は「遅く」、負値は「早く」を意味する。例えば開始から10秒後の投稿に＋2秒の補正を設定すると、再生位置12秒で表示する。

- 再生位置は、確定した基準位置＋単調増加時計で測った経過時間から計算する。
- タイマーが呼ばれるたびに一定秒数を加える方式は使わない。タイマー遅延を累積させないため。
- 初期版の速度は等倍とする。コメントが画面を横切る速度と、実況時間の進む速度を分離する。
- 一時停止時は再生位置と表示中コメントの移動を両方止める。
- 再開時は基準時計を張り直し、一時停止中の時間を進行に含めない。
- 実行中に補正を変えた場合は現在位置で描画状態を組み直す。以後の投稿だけ補正して表示中コメントが古い位置に残る状態を避ける。
- 補正で枠の外へ移ったコメントは枠内に押し込まず表示しない。初期版では指定放送枠外の投稿を補充しない。

### シークと巻き戻し

- シーク先は0〜再生時間の範囲に制限する。
- 操作前が停止中ならシーク後も停止、再生中なら再生を継続する。
- 待機キュー、表示中レス、既送信判定を再構築し、前の位置のコメントを残さない。
- 巻き戻したレスは再び表示できる。取得時の重複排除と再生時の既表示管理を分ける。
- 現在のスケジューラーは時刻の逆行を拒否するため、そのまま負方向へ進めず、再生成などで新しい再生世代へ切り替える。
- 推奨案は、シーク先の直前から画面内に残る可能性のあるコメントを限定範囲で再計算し、途中位置を復元する方式とする。
- 混雑時の割り当てが過去状態に依存する場合は、復元範囲やチェックポイント方式を検証する。全ログを毎回先頭から処理する構造は避ける。
- スライダー操作中の大量の再構築を抑え、ドラッグ確定時には必ず最終位置を反映する。

### 閲覧中のレスを指定して再生位置へ移動

スレッドを読みながら、場面の手がかりになるレスを見つけて実況の再生位置を移動できるようにする。初期版ではThreadViewの右クリックメニューに「この位置まで過去実況を再生」を追加する。

- 対象は読み込み済みの過去実況セッションに含まれるレスとする。スレッド識別子＋元レス番号で参照し、別スレッドの同じ番号を取り違えない。
- 移動先は「選択レスの投稿時刻 − 放送開始日時 ＋ 現在の同期補正」で計算する。例えば23:35:20の投稿、23:30開始、補正＋2秒なら05:22へ移動する。
- この操作は再生位置だけを変え、放送開始日時や同期補正は変更しない。「このレスを動画の今に合わせる」という同期設定操作とは区別する。
- 通常のシークと同じ処理を通し、再生中なら再生を継続、一時停止中なら停止状態を維持する。未来にも過去にも移動できる。
- 選択レスの予定表示時刻ちょうどへ移動した場合、そのレスをシーク済みとして読み飛ばさない。同時刻のレスも安定した順序で処理する。
- NGや混雑時の省略規則は維持する。指定したレスの強制表示は行わず、投稿時刻への移動と表示の保証を分ける。
- 元投稿が放送枠外、補正後の移動先が再生範囲外、投稿時刻が解析不能の場合は操作不可とし、理由を表示する。端へ丸めて別の位置に移動したように見せない。
- 再生設定がない、読み込み中、または対象スレッドがセッションに含まれない場合も理由を表示する。クリックだけでスレッドを追加取得したり設定を作り替えたりしない。
- スレッド画面と再生用スナップショットが一致しない場合は、再生側に対象レスがあるかを確認する。存在しなければ再読み込みが必要な旨を表示する。
- 移動後はコントローラーの経過時間・実況時刻を更新する。外部動画は移動しないため、操作説明に「実況コメントのみ移動」と明記する。
- 将来の連結閲覧からも同じレス参照と操作を呼び出せる形にし、通し番号には依存させない。

### 遅延・スリープ・終端

- フレームが遅れた場合は現在時刻へ追従し、通過したレスを一斉投入しない。
- 混雑時に何秒まで遅延を許すかを明示的な設定値として扱い、同期優先では期限を超えた待機レスを省略する。
- 省略件数を取得失敗・日時解析失敗と区別する。描画できない全件を永久に待たせない。
- スリープ等から復帰して大きな時計差を検出したら一時停止し、再同期を促す案とする。検出閾値は実機確認で決める。
- 終端では終了状態にして画面をクリアする。先頭へ戻す操作で同じ設定を再生できる。
- タイマー遅延が累積しないことと、外部動画との完全同期は別の保証である。動画停止・バッファリング・CMカットには手動調整が必要。

## 7. 取得、保存、エラー

- 既存のサービスコンテナを通じて取得し、利用できる保存済み過去ログを再利用する。UIから直接通信しない。
- URLごとの取得状態を管理し、同時取得数を制限する。再試行で成功したログまで再取得しない。
- 部分失敗時は黙って再生せず、失敗一覧を表示して「取得済みのログだけで再生」を利用者が選べるようにする。
- 対象レスが0件の場合は自動再生せず、時間範囲・日時解析失敗・取得結果を確認できるようにする。
- 読み込み中に設定を変えた場合は旧取得の完了結果を新設定へ適用しない。キャンセルと世代番号で制御する。
- NG判定や画像抽出は既存の処理を再利用する。NG除外件数と取得不足を混同しない。
- エラーは詳細をログへ出し、画面には対象と再試行方法を表示する。ログへレス本文全体を無条件に出さない。
- 保存内容は版番号、URL一覧と入力順、開始日時、再生時間、同期補正とする。
- 投稿データは既存キャッシュへ任せ、再生設定へ本文を重複保存しない。
- 再生位置を復元する場合も起動直後には自動再生しない。
- 保存データの検証と版管理を行い、破損時はエラーを記録して入力画面へ戻す。

### 複数ウィンドウ間の状態

- セッションの正本を一か所に置き、操作用と描画用で独立した再生時計を勝手に進めない。
- 通信にはセッション識別子、再生世代、順序番号を持たせ、シーク前の遅れて到着したイベントを破棄する。
- 異なるウィンドウの単調増加時計の値を同じ基準と仮定しない。描画側での時計同期方式を契約テストで確認する。
- Overlayの再作成・再接続時には現在位置と状態のスナップショットを送り、過去のイベント列への依存を避ける。
- ライブと過去再生は同時に同じOverlayへ送信しない。切り替えで前セッションを停止・購読解除・キュー破棄する。

## 9. 将来の連結閲覧とアンカー

共通化する単位は「順序付きのスレッド集合」と「取得元を保持するレス」である。

- スレッド集合: 識別子、正規化URL、入力順、取得結果。
- レス参照: スレッド識別子＋元レス番号。
- 再生用: 投稿日時による時刻順の表示。
- 閲覧用: スレッドの入力順と元レス番号による表示。

連結後の通し番号は表示用の派生値にする。スレッド追加・順序変更・欠損ログの補完で変わるため、永続的な参照キーにしない。

同一スレッド内の `>>50` は、そのレスが属するスレッドの50番として解決する。別スレッドを明示するリンクはリンク先に従い、単なる番号を前スレへの返信と推測しない。
本文のアンカーを書き換えず、内部参照を保持して必要な表示だけ変換する。元スレへの移動・コピー・既存ポップアップの意味を保つためである。

初期版で汎用的な連結閲覧フレームワークまで作らない。取得と識別の境界を共通利用できる状態にし、閲覧UIは別の実装単位にする。

## 10. 実装手順と段階ごとの完了条件

実装開始時は最新の `develop` と関連Issueを再確認し、承認された範囲を `ready-for-agent` のIssueとして扱う。各作業は専用ブランチで行う。

2. **ログ集合とタイムライン**

3. **再生セッションと時計**
   - 再生・停止・終端・シーク・同期補正、キャンセルと世代管理を実装する。

## 11. 検証計画

### 自動確認

- 時間範囲の開始を含み、終了を含まない。23:30〜翌00:00を正しく扱う。
- 複数スレッドの投稿時間が重なっても正しい時刻順になり、同時刻の順序が安定する。
- 同一スレッドの重複URLは除去し、別スレッドの同じレス番号・本文は保持する。
- 日時解析不能、取得失敗、範囲外、NG除外を区別する。
- 偽時計の飛び・遅いコールバック・停止再開で再生位置がずれない。
- ＋2秒の補正で予定表示時刻が2秒遅くなり、−2秒で早くなる。
- シーク・巻き戻し・補正変更・連続操作で旧世代のイベントや待機レスが残らない。
- レス指定シークで取得元と番号を正しく解決し、補正込みの予定時刻へ移動する。選択レスを境界で読み飛ばさず、再生・停止状態を維持する。
- レス指定シークの対象外スレッド、未取得レス、範囲外時刻、解析不能、未準備状態を区別し、設定や取得対象を暗黙に変更しない。
- 混雑時に遅延が蓄積せず、省略の集計が正しい。
- 部分失敗後の再試行、読み込みキャンセル、保存破損、Overlay再接続を確認する。
- ライブ／過去再生の切り替えと、既存ライブ実況の回帰を確認する。
- Main同期要求のセッションID・世代番号を検証し、古い要求を破棄する。
- Mainの通常タブを残したまま実況専用タブを作成し、同一セッションのスレ切替で同じタブを再利用する。

実装時は `pnpm exec vp check`、`pnpm exec vp test run` と関連ビルドを実施する。
PR前はAGENTS.mdの `pnpm lint`、`pnpm tsc` の要件を確認する。
調査時点の `package.json` には `tsc` スクリプトが見当たらないため、利用可能な実行形式を確認し、実行できなければその事実と代替の型検査を記録する。
`pnpm lint` は修正を伴う設定のため、実行後の差分を点検する。
Tauriのウィンドウ・通信に変更がある場合はTauriビルドと必要なRust側の検査も行う。ブラウザ版に影響する接続変更ではChrome・Firefoxビルドも確認する。

テスト名とコード内の意図コメントは日本語で記述する。fixtureは架空の日時・本文・予約済みドメインを使い、実在のスレッドを特定できるURLを含めない。

### 先行試作と今回の統合内容

正式な画面へ接続する前の手触り確認として、`src/features/comment-overlay/ui/OverlayStage.stories.tsx` の `PastThreadReplay` Storyを複数URL対応へ置き換えた。その後、同じドメイン処理を `src/features/archive-replay/` へ移し、Tauri版のコマンドパレットにある「過去実況再生を開く」から開けるようにした。コメントOverlay側には表示責務だけを残し、操作窓・Main同期・再生位置計算は過去実況機能へ集約している。

- URLを改行区切りで入力し、重複URLを除いて並行取得する。
- 日時解析後、指定した開始日時と再生時間へ絞り、全スレッドを投稿時刻順に混ぜる。
- 試作の開始日時は任意入力とし、空欄なら取得したログの最も早い有効な投稿時刻から開始する。放送開始を推測した値ではなく、手動指定で上書きできる。自動値は入力欄へ保存せず、次の読み込みごとに計算する。
- 入力欄は親の幅内へ収め、狭い表示領域では読み込みボタンと再生操作を折り返す。
- 取得失敗は成功したスレッドの再生を妨げず、失敗URLを表示する。全件失敗時だけ再生を開始しない。
- Storybookでは60倍を既定の試作倍率にし、30分枠を短時間で操作できるようにする。本番操作窓は等倍を既定にし、必要な場合だけ0.1〜10倍へ調整する。
- シークバー、10秒移動、1秒単位の早い／遅い補正、先頭再生を備える。
- 操作窓内にはレス一覧を置かず、ThreadViewの右クリックメニュー「この位置まで過去実況を再生」から取得元URLとレス番号を指定して、そのレスの投稿時刻へ移動する。
- シークはOverlayの表示世代を作り直すため、前の位置のactive・pendingコメントを残さない。
- 再生窓はコメントを描画せず、既存のコメントOverlayへreset/comment/playback/stop eventを送る。過去実況中はlive eventをOverlay側で受け付けない。
- 「現在の実況スレをメインで開く」は現在位置のスレをMainの専用タブへ一度だけ通知し、「メインを実況スレに追従」はスレ境界で同じタブを切り替える。
- Main同期通知にはセッションID・世代番号・取得元URL・元レス番号・タイトルを含め、Main側で同一セッションの古い通知を破棄する。

Storybookのfixtureは速度モデルの確認用として残し、実際のログ取得と再生操作はTauri版の独立操作窓で行う。ブラウザ版ではコマンドを一覧から除外し、再生窓も表示しない。設定保存、再接続、スリープ復帰は未接続である。

### 人による確認

1. 30分間にまたがる複数スレッドを入力し、設定した放送日時で再生する。
2. スレ移行箇所で時間の巻き戻りや不自然な待ちがないことを確認する。
3. 動画と同時に開始し、開始直後・中盤・終盤で同期の体感を確認する。
4. 動画を止めて実況も止め、再開してコメント位置が保たれることを確認する。
5. 10秒移動と1秒補正を使い分け、巻き戻したコメントが再び流れることを確認する。
6. コメントが集中する場面で遅延が増え続けないことを確認する。
7. CMがカットされた動画では手動シークが必要であることを確認する。
8. 取得失敗・日時不正・0件の説明から、設定変更や再試行へ進めることを確認する。
9. ウィンドウの閉じる・再表示・複数モニター・スリープ復帰を確認する。
10. 過去再生を終了し、ライブ実況が従来どおり動くことを確認する。
11. 閲覧中のレスから時刻へ移動し、別スレッドの同じレス番号と混同せず、補正を反映した位置になることを確認する。停止中・再生中の両方で試し、外部動画は動かないことも確認する。
12. 「現在の実況スレをメインで開く」でMainに専用タブが作られ、通常の閲覧タブが上書きされないことを確認する。同じ再生セッションで次スレへ進んだときは専用タブだけが切り替わることを確認する。

## 12. 残る判断とリスク

| 項目 | 推奨案・残る確認 |
| --- | --- |
| 初期対象 | Tauri版。ブラウザ版への提供は別検討 |
| UI形態 | Tauriの独立操作ウィンドウへ接続済み。設定の折りたたみは後続検討 |
| 日時入力 | 日本時間の日付＋開始時刻＋再生時間。初期値30分 |
| 保存 | まず直近の設定を復元できる範囲。複数プリセットの管理は別検討 |
| 混雑 | 同期優先で期限切れを省略。許容遅延と表示密度の初期値は視聴確認で決める |
| シーク復元 | 画面内に残るコメントを再構築。再計算コストとレーンの再現性を検証 |
| 外部動画 | 停止・シーク・CMカットを自動検出できないため手動操作が必要 |
| 投稿の遅れ | 投稿時刻は映像中の出来事の時刻そのものではない。反応・入力の個人差は一律補正で解消しない |
| 過去ログ取得 | 保存済みログや取得先の状態に依存する。取得不能を再生UIだけでは解決できない |
| 連結閲覧 | スレッド集合・レス参照のみを共通化し、表示機能は別工程 |
| Main同期 | 現在はスレッド切替と元レス番号を通知する。Main側で該当レスまで自動スクロール／強調する処理は後続検討 |
