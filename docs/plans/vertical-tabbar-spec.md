# 垂直タブバー仕様案

## 目的

- 水平タブバー（現状の `TabBar`）に加えて、垂直配置のタブバーを選べるようにする。
- スレ・板を多数開く使い方で、タイトルが省略されにくく、タブの見通しを良くする。
- `.todo` にある関連要望と競合せずに共存できる配置を決める。
  - `vscodeみたいにタブバーの一段上に細いタイトルバーを設置`（Issue #80）
  - `タブバー右端に表示されているアイコンをchromeのように表示・非表示を切り替えられるように`（Issue #81）
  - `汎用左サイドバー＆お気に入りビュー`（Issue #82）

## 現状整理

- `src/view/browser/App.tsx` の `PaneColumnInner` が `pane-column__chrome` 内に `TabBar` と `NavigationBar` を縦に積んでいる。
- `src/view/browser/components/TabBar.tsx` は水平前提である。
  - `DragDropProvider` + `useSortable` で水平ドラッグし、ピン留めと通常を `group` で分離する。
  - ホイールはタブ切り替えに使っている（`normalize-wheel` で正規化し、横スクロールではなく `SELECT_TAB` を発火）。
  - 横はみ出し時は `scrollIntoView` と左右のグラデーション表示で追従する。
  - 新規追加ハイライト、自動更新インジケーター、中クリックで閉じる、右クリックメニューを備える。
- `src/view/browser/styles/components/TabBar.css` は高さ `var(--sys-space-13)` の横ストリップ固定である。
  - タブ幅は `flex: 0 0 180px`、最小 `72px`、最大 `180px`、アクティブ時だけ最大 `240px`。
  - ピン留めは `36px` の正方形扱い。
  - アクティブ表示は下辺 `2px` のアクセント色である。
- `src/view/browser/hooks/use-tab-store.tsx` のタブ操作自体は方向に依存しない。
  - `MOVE_TAB` はグループ内インデックス基準であり、水平・垂直どちらでも流用できる。
  - ペイン分割は `MAX_PANES = 2` の横並び固定である。
- `src/view/browser/styles/layout/PaneLayout.css` の `pane-column` は縦カラム、`pane-row` は横並びである。

## 用語

- 水平モード: 現状の上部タブストリップ。
- 垂直モード: ペイン左端に置く縦方向のタブ一覧。
- 展開表示: タイトル全文に近い幅（例: `200px` 前後）で表示する状態。
- 簡易表示: アイコン中心の細幅（例: `48px`）で表示する状態。

## 要件

### 機能要件

1. タブバーの方向を水平と垂直で切り替えられる。
2. 切り替えは再起動なしで即時反映される。
3. タブの基本操作は方向を変えても同じである。
   - 選択、閉じる、中クリックで閉じる、ピン留め、ドラッグ並べ替え。
   - 新しいタブ、閉じたタブを開く、コンテキストメニュー。
   - 自動更新インジケーター、新規タブのハイライト、ツールチップ。
4. 垂直モードでもピン留めと通常タブの境界は維持する。
5. 2ペイン時も各ペインのタブ独立性は維持する。
6. 方向設定は永続化される。

### 非機能要件

1. 既定値は水平モードとし、既存利用者の見た目を変えない。
2. タブ操作の状態管理（`use-tab-store`）に破壊的変更を加えない。
3. キーボード操作とスクリーンリーダー向けの属性を水平モードと同等以上に保つ。
4. 垂直モードでもタブ追加・切り替え時の追従スクロールが破綻しない。

### 対象外

1. 汎用左サイドバー（Issue #82）そのものの実装。
2. タイトルバー一段化（Issue #80）や右端アクションツールバー集約（Issue #81）の実装。
3. タブのツリー化、グループ化、アコーディオン化。
4. タブのサムネイルプレビュー。

## 仕様案

### 配置の基本方針

- 第1段階はペイン内縦配置とする。
  - 各 `PaneColumn` でタブバーを左端の上端まで伸ばし、右側にタイトルバー以下を積む。
  - タブバーはシェルの上端まで届き、タイトルバーを右へ押しのける。
  - 理由: タブ状態がペイン単位であり、シェル共有の1本化より既存構造と整合する。
- シェル共有の1本サイドバー化は採用しない。
  - 理由: 2ペイン時にどちらのペインのタブを出すかという所有関係が増え、操作対象の混乱を招く。
- 垂直モードではタイトルバーもペイン単位にする。
  - シェル共通の `TitleBar` は表示せず、各ペインが自ペインのタイトルと操作欄を持つ。
  - 1ペイン優先の簡易対応とし、2ペイン時は操作欄が複製される。
- 画面全体の左から右への並びは以下を想定する。
  - `[汎用サイドバー（将来）] [垂直タブバー（ペイン単位）] [タイトル/ナビゲーション/本文/下部パネル]`
  - 垂直タブバーと汎用サイドバーは別物として共存させ、今回で統合しない。

### 方向設定

- 設定キーは `tab_bar_orientation` とし、値は `horizontal` と `vertical` の2値にする。
- 既定値は `horizontal` とする。
- 設定場所は既存のタブ・表示設定の近く（`settings-sections.tsx` のタブ動作系）に置く。
- 設定変更は即時反映し、リロードやセッション復元を要求しない。
- 設定値は `Store2` の `config_` 系と同じ経路で永続化する。
- ペインごとの個別方向は第1段階では持たない。
  - 理由: ペイン間で方向がばらつくとレイアウト検証と操作説明が複雑になる。

### 垂直モードの寸法

- 展開幅の既定値は `208px`、最小 `160px`、最大 `280px` を目安にする。
- タブ1行の高さは `32px` を目安にし、行間を詰めすぎない。
- 簡易表示の幅は `48px` を目安にする。
- 高さ方向はペインの高さいっぱいを使い、横スクロールを出さない。
- 2ペイン時に横幅が厳しい場合の救済策は、自動で水平へ戻すのではなく簡易表示への縮退を優先する。
  - 勝手に方向が変わると利用者の予測を裏切るため。

### タブ行の表示

- 1行は `[状態色] [アイコン] [タイトル] [自動更新表示] [閉じる]` の順にする。
- アクティブ表示は下辺ではなく左辺のアクセント線にする。
  - 理由: 縦一覧では左辺のほうが走査しやすく、水平モードとの視覚的な区別にもなる。
- タイトルは1行省略を基本にし、折り返しはしない。
- ピン留めタブは一覧の上部にまとめて表示する。
  - 水平モードの左端グループと同じ意味を、垂直モードでは上端グループとして再現する。
  - ピン留め行はアイコン中心の正方形に近い扱いとし、通常タブと高さを完全一致させなくてよい。
- ページ種別アイコン（板、スレ、ホーム、板一覧など）は `.todo` の既存要望と重なるため、垂直化と同時に新規追加しない。
  - 将来のアイコン追加で破綻しないよう、アイコン用の leading 領域だけ確保する。

### 操作仕様

- クリックで選択、中クリックで閉じる、右クリックで個別メニューは維持する。
- ドラッグ並べ替えは垂直軸で行う。
  - `dnd-kit` の sortable 方向設定だけを切り替え、移動確定の考え方は変えない。
  - ピン留めと通常の境界越えは引き続き禁止する。
- ホイール操作は水平モードと仕様を変える。
  - 水平モード: タブ切り替え（現状維持）。
  - 垂直モード: 一覧の縦スクロールを優先しつつ、スクロール不要時や端到達時はタブ切り替えに使う。
  - 理由: 縦一覧の上でホイールを回したとき、スクロールが起きずにタブだけ切り替わると予測とずれるため、
    スクロール可能な間は既定スクロールへ任せる。一方でスクロール先がない場合は何も起きないより
    タブ送りできた方が自然なため、端や非スクロール時は切り替える。
  - 横方向のホイール（Shift+ホイール含む）は常にタブ切り替えに使う。
  - 代替の切り替え手段は `Ctrl+Tab` 系や上下矢印キーも維持する。
- 新規追加ボタンは垂直バーの最終タブの直後に置く。
  - 一覧と一緒にスクロールさせ、タブの並びの延長として操作できるようにする。
- 更新ボタンはタイトルバーの左端に置く。
  - 垂直バーの上部には置かず、タイトルバー行の左端から再取得できるようにする。
  - 無効化条件は現状の `canRefresh` と同じにし、判定は `isPageRefreshable` で共有する。
- 展開と簡易表示の開閉ボタンは、高さをタイトルバーのボタンに揃え、横幅はバーいっぱいに広げる。
- 空白部右クリックのバー背景メニュー（新しいタブ、閉じたタブを開く）は維持する。
- 新規タブ追加時のハイライト（約 `1.5秒`）と表示位置への追従は維持する。
  - 追従方向だけ `inline` から `block` 中心へ変える。

### ハンバーガーメニューとURLバー用chevronの扱い

- 現状の2つのボタンはどちらも `src/view/browser/components/NavigationBar.tsx` にある。
  - ハンバーガー: `nav-bar__btn` の `Menu` ボタン（`handleMenuClick` で `ContextMenu` を開き、ヘッダーに戻る/進む/更新/お気に入り/設定を出す）。
  - chevron: `nav-bar__url-toggle` の `ChevronDown/Up` ボタン（`handleUrlBarToggle` で `Omnibar` の入った `nav-bar__url-row` を開閉する）。
- 垂直モードでは、この2つのボタンを自ペインの `TitleBar` の右端（ペイン分割ボタンの左隣）へ移動する。
  - 狙い: ペインごとの上部クロームをなくし、上のバーをできるだけ薄くする。
  - 垂直タブバー側へ入れない理由: URL入力は横幅が必要で縦棒に入らず、メニューはタブ一覧ではなくペイン操作全体に関わるため、縦棒の上下固定領域に入れると配置が不自然になる。
  - 2ボタンは小型化し、並び順はchevron→メニューとし、分割ボタンの左隣にメニューが来るようにする。
- 垂直モードの `NavigationBar` はボタン行を持たず、URL展開時のオーバーレイ表示だけを担当する。
  - 平常時はペイン上部のボタン行を表示せず、その分の高さを本文へ返す。
  - chevron操作で開いた `Omnibar` は `TitleBar` 直下の全幅オーバーレイとして出し、ペイン上部に行を追加してガタつかせない。
  - オーバーレイはフォーカスアウトで閉じて本文へ返す（水平モードはchevron操作でのみ開閉）。
- 操作対象は自ペインとする。
  - タイトルバーがペイン単位のため、各ペインのボタンは自ペインに作用する。
  - 非アクティブペインのメニューも直接開ける。
- 実装方式はポータル方式とする（実装済み）。
  - `NavigationBar` のReactツリー上の位置は変えず、描画先だけ自ペインの `TitleBar` の `.title-bar__nav-slot` へ `createPortal` する。
  - 理由: ペインスコープの各プロバイダ（タブ状態・下部パネル等）をそのまま利用でき、ロジックの切り出しが不要になる。
  - 受け口はペインごとに分かれるため、アクティブ切り替え時の表示制御は不要である。URL展開状態はペインごとに保持する。
  - スロットが無い環境では従来どおりインライン表示へ縮退する。
- 移設に伴う実装上の注意点は以下とする。
  - `useUrlBarVisibility` はペイン単位の開閉を保持しているため、`TitleBar` のchevronはアクティブペインの開閉だけを切り替える。
  - `.title-bar` に `position: relative` を付け、URL行オーバーレイの配置基準にする（`z-index` は付けず既存の重なり順序を保つ）。
  - ペイン上部の空になった `pane-column__chrome` は `:empty` のときだけ畳む。
  - `ToastProvider` の `topOffset` は `isUrlBarExpanded` に応じて変えているため、オーバーレイ化後の重なりを確認する。

### スクロールと追従

- 垂直モードの一覧は `overflow-y: auto`、`overflow-x: hidden` とする。
- スクロール可能表示は左右グラデーションではなく上下グラデーションに置き換える。
- 既存の `canScrollLeft/Right` 相当を `canScrollTop/Bottom` として持ち替える。
- アクティブタブ追従は上下の見切れ判定だけにし、不要なスクロールで手動位置を奪わない方針は維持する。
- `ResizeObserver` とウィンドウリサイズ時の再評価は方向を問わず維持する。

### キーボードとアクセシビリティ

- 一覧に `role="tablist"`、`aria-orientation="vertical"` を付ける。
- 各タブに `role="tab"` と `aria-selected` を付ける。
- 上下矢印キーで前後タブへ移動できるようにする。
  - 水平モードの左右移動と対称の操作にする。
- フォーカス表示はマウス用 hover とは別に視認できる outline を残す。

### 設定と永続化

- 永続化対象は方向のみを必須とし、幅と簡易表示状態は次の順で扱う。
  - 第1段階: 方向のみ永続化する。
  - 第2段階: 展開幅と簡易表示の開閉も永続化する。
- 理由: 第1段階で永続化項目を増やすと、設定移行と不整合時の復旧条件が増える。
- セッション復元（タブ内容自体）の形式は変えない。

## 技術設計案

### コンポーネント

- `TabBar` に `orientation` プロパティ（`horizontal | vertical`）を追加する。
- 方向分岐は描画とスクロール系フックの範囲に閉じ込める。
  - タブ選択、閉鎖、ピン留め、メニュー、自動更新表示の判定は共通化する。
- `SortableTab` の行レイアウトは CSS クラスで切り替え、ドラッグ処理の本体は共通化する。
- 方向特有の数値（しきい値、クールダウン、ハイライト時間）は定数として分離する。
  - ホイール切り替え用定数は水平モード専用であることを名前やコメントで明示する。

### レイアウト変更

- `PaneColumnInner` を以下へ変える。
  - 現状: `pane-column__chrome`（`TabBar` + `NavigationBar`）の後に `ContentArea` を置く縦積み。
  - 垂直時: 左に `TabBar`、右に `NavigationBar` 以下を置く横並びの内側ラッパーを追加する。
- `PaneLayout.css` に垂直時専用の行レイアウトを追加する。
  - 既存の水平用クラス名や DOM 取得に依存する処理を壊さないため、方向クラスは追加方式にする（例: `pane--vertical-tabs`）。
- `TabBar.css` は方向クラスで分岐する。
  - 共通: タブの選択色、hover、ハイライト、ドラッグ中表示、閉じるボタン。
  - 水平専用: 横幅 `180px` 系、左右グラデーション、下辺アクセント。
  - 垂直専用: 行高 `32px` 系、上下グラデーション、左辺アクセント。

### 状態管理

- `use-tab-store` の reducer と action は変更しない。
- 方向はタブ状態ではなく表示設定として扱う。
  - 既存の `config_` 読み書きと同じ層に置く。
- 将来の幅リサイズ対応は、タブ状態ではなく `TabBar` 内部状態 + 設定永続化で行う。

## 関連要望との整理

- Issue #80（タイトルバー一段化）とは直交させる。
  - 垂直化でタイトルバーは作らず、将来の上部共通バーの下に垂直タブバーを置ける形を残す。
- Issue #81（右端アイコンの表示切替）とは結合しない。
  - 更新・追加ボタンの垂直バー内配置は、右端ツールバーの仕様確定を待たずに決めてよい。
- Issue #82（汎用左サイドバー）とは統合しない。
  - 汎用サイドバーが来ても、左から `[サイドバー][垂直タブバー][本文]` と並べられる余地を残す。
  - タブをお気に入りと同じツリーに入れる案は第1段階の対象外とする。

## 段階的な進め方

### 第1段階: 方向切り替えの最小実装

1. 方向設定を追加し、水平を既定にする。
2. ペイン内縦配置のレイアウトを追加する。
3. 垂直用の行表示、左辺アクセント、上下スクロールへ対応する。
4. ドラッグの垂直軸対応とホイール仕様の分離を行う。
5. ハンバーガーメニューとURLバー用chevronを `TitleBar` 左上へ移し、垂直モードのペイン上部ボタン行をなくす。
6. 既存のタブ操作テストを方向違いでも通す。

### 第2段階: 使い心地の調整（実装済み）

1. 展開と簡易表示の切り替えを追加する。
   - 垂直バーの上部ヘッダーにある開閉ボタンと設定画面（`tab_bar_collapsed`）の両方から切り替える。
   - 簡易表示は幅 `48px` 固定で、タイトルと閉じるボタンを隠してページ種別アイコンのみ出す。
   - 閉じる操作はホバーのみ重ねて出し、中クリックと右クリックは従来どおり使える。
   - タイトル確認は既存のカーソルツールチップと `aria-label` で行う。
2. 展開幅のドラッグリサイズを追加する。
   - 右端の専用ハンドルだけで開始し、タブのドラッグ並べ替えと干渉させない。
   - 範囲は `160px` から `280px` に収め、ドラッグ中だけ操作幅で描画する。
   - ハンドルは縮小時も出し、右へ引く操作で展開へ移れるようにする。
   - 掴みどころが分かるよう、通常時も細い線を見せておく。
3. 幅と開閉状態の永続化を追加する。
   - `tab_bar_collapsed` と `tab_bar_width` を設定として保存し、再起動後も維持する。
   - 幅はドラッグ確定時だけ保存し、移動中の連続書き込みを避ける。
4. 2ペイン時の狭幅条件での縮退ルールを決める。
   - 第2段階では手動切替のみとし、自動縮退は見送る。
   - 理由: 自動と手動の競合解決が複雑になり、2ペインでも手動で畳めるため。

### 第3段階: 周辺統合の検討

1. 汎用サイドバーとの並び順や開閉連動を検討する。
2. タイトルバー一段化と更新・追加ボタンの置き場所を再検討する。
3. ページ種別アイコンの導入を検討する。

## 確認項目

- 水平モードの見た目と操作が変わっていない。
- 垂直モードで全タブ操作が水平モードと同じ結果になる。
- ピン留めの境界を越えたドラッグができない。
- タブが長い場合も上下スクロールと追従が破綻しない。
- 2ペインで左右それぞれの垂直タブバーが独立に動く。
- 方向切り替え直後にリロードしても方向が維持される。
- 垂直モードで `TitleBar` 左上のメニューとchevronがアクティブペインに対して動く。
- 垂直モードでURL展開時にペイン上部へ行が追加されず、オーバーレイで表示される。
- 既存の `TabBar.test.tsx` とタブストア関連テストが通る。

## 残存リスク

- 2ペイン + 垂直タブバーでは本文幅が狭くなり、スレ本文や表の可読性が落ちる。
- 垂直モードのホイールをスクロール専用にすると、水平モードの癖でタブ切り替えを期待する利用者が戸惑う。
- 幅リサイズを第1段階に入れると、ドラッグとタブのドラッグ並べ替えの当たり判定が干渉する。
- 将来の汎用サイドバーと合わせると左端の幅合計が大きくなり、全体レイアウトの再調整が必要になる。

## 未確定事項

1. 垂直モードの既定幅と簡易表示の要否。
   - 既定は簡易表示（縮小モード）とし、本文の幅を優先する。展開幅の既定は `208px` とする。
2. `TitleBar` 右端へ移した2ボタンの並び順と `TitleBar` 中央タイトルとの視覚的な区切り。
   - ペイン分割ボタンの左隣に `[chevron][メニュー]` の順で置き、タイトル中央配置は維持する。
3. 簡易表示でのタイトル確認手段。
   - 案: 現状のカーソルツールチップをそのまま使い、別仕様は作らない。
4. 2ペイン時の狭幅ルール。
   - 案: ペイン幅の実測値で簡易表示へ自動縮退し、方向自体は変えない。
5. 垂直モード専用ショートカットの要否。
   - 案: 第1段階では増やさず、要望が出てから検討する。
6. `TitleBar` 集約が複雑になった場合に縮退案（`NavigationBar` 据え置き）へ切り替える基準。
   - 案: ペインスコープやオムニバー配置の変更が大きくなったら、垂直タブ本体を優先して縮退案にする。
