# サイドパネルとサブレンズの実装計画

## 目的と範囲

スレッド本文を表示したまま、画像、抽出レス、スレプロパティを参照できる右サイドパネルを作る。パネル上端の背景なしアイコンでビューを切り替える。見た目の検討結果は [画面案 D](../mockups/sublens-layouts.html) を参照する。画面案のサンプル値やアイコンは確定仕様ではない。

[#198](https://github.com/22-2/ChLens/issues/198) のサブレンズと、[#82](https://github.com/22-2/ChLens/issues/82) の汎用サイドバーは外枠の設計を共有する。お気に入り自体は #82 の範囲とし、重複実装しない。書き込みのサイドパネル対応は後続段階とする。Tauri・Chrome・Firefox のアプリ内 UI を対象とし、ブラウザ固有のサイドパネル API には依存しない。

## 操作仕様

- 右サイドパネルはタイトルバー右上のハンバーガーメニューの右隣に置く `PanelRightOpen` / `PanelRightClose` アイコンで開閉する。状態に応じてアイコンと操作名を切り替え、ツールチップとアクセス可能な名前を付ける。幅変更ができ、開閉状態、幅、選択ビューを復元する。閉じても本文や自動更新は維持する。
- ビューはアイコンを選んで切り替え、ドラッグで並べ替えられる。並び順と開いているビューを保存・復元し、キーボードでも並べ替えられる操作を用意する。選択中を下線で示し、ツールチップとアクセス可能な名前を付ける。対象のスレッド名や「追従」バッジを常時表示しない。
- 初期状態ではパネルはウィンドウごとに１つ。２ペインでは最後に操作したペインの選択中タブに追従する。パネル操作自体は対象ペインを変更しない。スレ以外ではスレ依存ビューに対象がないことを示す。
- 対象切替時に古いスレの情報を新しいスレの情報として表示しない。表示中のデータとエラーは対象 ID と結び付ける。取得中、取得失敗、該当なしを区別し、失敗時は再試行を提供する。
- 狭い幅や２ペインでは本文の最小幅と閉じる操作を確保する。重ね表示への切替条件は実画面で決定する。縦・横タブバー、別窓、Zen モードも確認する。

### タイトルバーの共通化

縦タブ・横タブのどちらでもタイトルバーをウィンドウ内に１つ置き、２ペイン時は操作中ペインの選択タブのタイトルと操作を表示する。戻る・進む・更新、タイトル右クリック、オムニバー、ハンバーガーメニューの操作対象も同じタブに揃える。左右ペインを操作したときに表示と対象が切り替わる。フォーカス移動やメニュー・入力中に対象が変わる場合の扱いは、誤操作と入力喪失を避けるよう検証して確定する。

現状は横タブ時は共通バー、縦タブ時は各ペインのバーであり、`NavigationBar` はペイン ID ごとのポータル先を使う。共通化ではアクティブなペインの操作だけを表示し、非アクティブのポータルが競合しないよう再設計する。縦タブバーと共通タイトルバーの位置関係、別窓、Zen モード、ウィンドウ操作やドラッグ領域への影響も確認する。

### 板一覧ツリー

板一覧をサイドパネルのビューとして追加し、メニュー・カテゴリを展開して板を選べるようにする。板名の入力で即時絞り込み、検索中は一致するカテゴリを開き、検索終了時に元の開閉状態へ戻す。板の選択は操作中のペインに対して既存の遷移規則を使い、新規タブ操作も既存動作に揃える。お気に入りの星や再取得は既存機能を調査して対応範囲を決める。板一覧は特定スレッドに依存せず、スレ以外の画面でも使える。

既存の `BoardListPage` は `pages/board-list/` の取得・フィルタ・開閉状態と表示部品を組み合わせている。`container.bbsMenu`、更新通知、検索処理は再利用候補。ページ配下を新しい feature から直接参照せず、共通化する処理を `features/board/` 等の適切な機能境界へ移し、通常ページとパネルが利用する。ページ向けアコーディオンをそのまま狭いツリーに流用できるとは限らないため、ロジックの共有と表示の再構成を分けて判断する。開閉・検索状態の共有範囲、既存ページとの更新同期、削除・お気に入り・右クリック操作の扱いは実装前に決める。

### 抽出レス

入力に応じてリアルタイムに絞り込み、一致箇所をハイライトする。空欄は結果も件数も表示しない。レスを選択すると対象ペインの該当レスにジャンプする。検索対象（本文・名前・ID）と既存検索との違いは実装前に確定する。検索語とスクロール位置は対象ごとに保持し、ビュー切替後も復元する。NG や既存フィルタとの関係は既存の検索挙動を調査して決める。

### 画像ギャラリー

サムネイルのみをタイル表示し、ホバーまたはキーボードフォーカス時にレス番号と省略した本文を表示する。タッチ環境の情報表示手段も用意する。クリックは既存の画像ビューアへ接続し、本文のレスへ移る操作も提供する。複数画像、重複 URL、画像以外のメディア、NG、取得失敗、手動取得設定、画像が多い場合の仮想化を検討する。判定と取得の仕様を既存表示に揃え、勝手に画像を追加取得しない。

### スレプロパティ

スレ名、板、URL、作成日時、経過時間、最終レス日時、レス数、未読数、状態、勢いとグラフ、画像・動画数、最終更新日時を候補とする。各項目は取得元と意味を調べ、利用できないものは不明とする。スレ ID から作成日時を推定できる形式もあるが、すべての板に適用しない。勢い・グラフの定義と期間を明示し、既存表示と計算を共有する。

### 書き込み（後続）

下部・サイド・別窓は同じ書き込みセッションの表示先とし、編集欄は原則１か所に置く。ほかの場所で開こうとした場合は現在の場所を示し、「こちらに移動」を提供する。移動時に下書き、投稿先、送信状態を失わない。ペインの操作だけで入力中の投稿先を変えず、投稿先を明示し変更操作を用意する。既存の URL ごとの下書きと再起動時に復元しない挙動を維持する。送信中の移動・二重送信、返信挿入、別窓終了時の扱いを実装前に定義する。

### お気に入り

既存のお気に入りデータをサイドパネルから参照し、板・スレを操作中のペインで開く。通常ページとの追加・削除・更新を同期し、既存の右クリック操作を再利用する。通常ページの表を狭い領域へそのまま流用せず、データ取得・正規化・操作を共有し、表示はパネルに合わせる。

## 設計の境界

- 外枠は開閉、幅、選択ビューと配置を担当し、ビュー固有の処理を持たない。開いているビュー、順序、選択、各インスタンス状態は統合されたビュー状態に保存する。既存の `TabViewState` はタブ・ページ単位なので、そのままウィンドウ共通パネルに格納せず、セッション永続化と他の表示状態を調査して適切な所有範囲を定める。保存が分散していれば旧形式の互換性を維持せずに段階的に統合する。保存済みの表示状態はリセットされてよい。組み立ては `src/view/browser/shell/` と App で行い、機能の UI と状態は各 `src/features/` に置く。
- ビューの種類とインスタンス ID、表示場所、対象を区別する。初期版は固定ビュー一覧・各種１つ・アクティブペイン追従でよい。複数インスタンスや固定対象は将来の拡張として扱い、未使用の複雑な基盤や公開プラグイン API は作らない。
- スレッド取得と自動更新の所有者は１つにし、表示部品は共有済みのスナップショットを参照する。パネル側から `useThreadData` を重複起動しない。ペイン ID・タブ ID・スレッド ID を区別し、同じスレを複数ペインで開いた場合もジャンプ先と表示状態が混ざらないようにする。
- サブスクライブ解除、タブ切替・閉鎖、別窓移動、非表示タブの寿命を明確にする。レス更新頻度に応じて不要な再描画を抑え、共有状態に DOM や更新制御の所有権を混ぜない。
- 機能間依存は一方向に保ち、必要な公開モジュールだけ `vite.config.ts` の `FEATURE_PUBLIC_MODULES` に登録する。純粋処理と状態を持つ処理は既存の core / サービスコンテナ規則に従う。色・寸法は既存のデザイントークンを使う。

## 既存資産と調査箇所

- `src/view/browser/App.tsx`：ペインとプロバイダの配置。`shell/BottomPanel.tsx` はパネル開閉・サイズ変更の参考。
- `src/view/browser/pages/ThreadPage.tsx` と `src/features/thread/browser/use-thread-data.ts`：レス、更新、読み込み状態の所有箇所。共有境界を比較し、既存の更新・キャッシュ・過去ログの挙動を壊さない方法を選ぶ。
- `src/features/thread/domain/thread-find.ts` と `src/view/browser/utils/search-highlight.ts`：検索と強調。`src/view/browser/utils/thread-read-state.ts`：タブ指定ジャンプ。
- `src/features/media/ui/ResMediaGallery.tsx`、`ExternalImage.tsx`、メディアビューア：画像の識別、取得方針、表示・拡大を調査して共有する。
- `src/features/thread/ui/IkioiStatusItem.tsx`：勢い計算とグラフ。計算と表示部品を切り出し、既存のステータスバーと共有する。
- `src/features/write/browser/use-write-session.tsx` と `src/features/write/ui/WritePanelContent.tsx`：下書き・投稿先の共有、既存の別窓制御。下部パネルへの依存を整理する。
- `src/view/browser/pages/BoardListPage.tsx` と `pages/board-list/use-board-list-logic.ts`、`use-board-list-display.ts`：板一覧の取得、更新通知、検索と開閉状態。共有境界への移設を検討する。
- `src/view/browser/pages/BookmarkListPage.tsx`、`FavoriteBoardsSection.tsx`、`src/features/bookmark/ui/BookmarkContextMenu.tsx`：サービスコンテナのお気に入り取得、更新通知、正規化、右クリック操作を共有する候補。ページ固有のロジックは機能側へ抽出する。
- `src/features/tabs/ui/TabBarView.tsx`：既存の `@dnd-kit/react/sortable` による並べ替えを参考に、共通化できる部分を調査する。通常タブ固有のピン・ペイン移動をサイドパネルに持ち込まない。
- `src/view/browser/types.ts` と `state/tabs/`：既存のタブ単位ビュー状態とセッションの保存・復元。パネル状態との所有範囲と移行を調査する。

## 調査結果と実装方針

### 表示状態の保存

- `tab-store-session.ts` は `chlens_browser_session` にペイン・タブ・ページ単位の `viewStates` を保存する。履歴から到達できないページ状態は保存時に削除し、実行時状態は保存しない。旧形式の復元にも対応している。
- 下部パネルは `chlens_bottom_panel_v1`、板一覧の開閉は `board_list_open_states` に保存しており、表示状態は分散している。下部パネルの Provider はペイン単位だが保存キーは共通で、別窓のレイアウトは保存から分離している。
- 方針：ブラウザセッションにウィンドウ共通のビュー状態を追加し、右パネルの開閉・幅・ビューの ID、種類、順序、選択を保存する。抽出語などの対象別状態はタブ・ページ単位で持ち、履歴剪定と閉じたタブの復元規則に合わせる。レス本体、通信中状態、下書き本文は保存しない。未知のビュー、不正な幅、保存値がない場合の既定値を検証する。
- 下部パネルと板一覧の開閉も所有範囲を整理して段階的に統合する。旧形式の読み込みや移行は不要とし、新形式の正本に統合する。既存の表示状態がリセットされることを前提に、再起動、失敗時、別窓の上書き、複数 Provider を検証する。削除設定や自動更新間隔は利用者設定として残す。複数ウィンドウの保存競合を調査し、独立した read-modify-write による上書きを避ける。

### スレッドデータの共有

- `ThreadPage` が `useThreadData` と更新コントローラを所有し、レス・取得状態はフック内にある。DOM 選択の復元、NG・絞り込み、タブ状態、通知にも依存するため、フックを単純に上へ移すことも２回呼ぶこともしない。
- 初期方針：既存の `ThreadPage` を取得・更新の所有者に保ち、必要最小限の読み取り専用スナップショットをシェル側へ公開する。タブ ID とページ識別子・URL を結び付け、所有者トークンによって古い解除が新しい登録を消さないようにする。同じスレを複数タブで開いても別々のスナップショットを参照する。これはパネルの追加取得を避ける仕組みであり、タブ間の通信統合ではない。
- 取得状態とレスを対象に紐付け、切替直後に古いレスを表示しない。購読解除、非表示タブ、更新頻度を検証する。DOM ref や更新操作は公開しない。別 WebView の分離タブは既存の通信経路を調査し、初期版で対応できなければ対象外として明示する。
- レスジャンプは既存の `requestThreadResJump` に対象タブ ID を渡す。ただし保留要求は URL 単位なので、同一 URL の複数タブへの同時要求を検証し、必要ならキーを見直す。フィルタで対象が見えない場合の解除も定義する。

### タイトルバーと対象切替

- 横タブ時は共通 `TitleBar`、縦タブ時は各ペインの `TitleBar`。`PaneProvider` のない `useTabStore` はアクティブペインを参照する。
- `NavigationBar` はペイン単位 Provider 内にあり、ペイン ID 付きのタイトルバー受け口へポータルする。横タブではアクティブペインの受け口だけがあり、非アクティブ側の操作欄は隠す。
- 方針：タイトルバーを両配置でシェル直下に１つ置き、既存の受け口を縦タブにも拡張する。NavigationBar は各ペインの Provider 内に残し、選択中のものだけ表示する。開閉ボタンはナビゲーション用スロットの右に置く。切替時の古いポータルやメニューの残留を防ぐ。
- オムニバーやメニューを開いたまま別ペインを操作したときは、元の操作を閉じて入力を破棄する案とする。別ペインへ入力や操作対象を勝手に引き継がない。入力破棄の UX、キーボード切替、Zen、分離タブ、右クリックとウィンドウ操作を実画面で検証する。

## 実装順序と完了条件

既存の表示状態の保存形式との互換性は不要とし、表示状態のリセットを許容する。旧形式の移行コードは作らない。お気に入り、履歴、キャッシュなど表示状態以外のデータは対象外とする。各段階で適切なテストと実画面確認を行い、問題を修正してから次へ進む。

### 1. タイトルバーの共通化

縦・横タブのどちらもタイトルバーをウィンドウに１つ設置する。２ペインでは操作中ペインのタイトル、戻る・進む・更新、メニュー、オムニバーを表示・操作できるようにする。入力中のペイン切替、別窓、Zen モード、キーボード操作を確認する。ここではパネル本体に依存させない。

### 2. 表示状態の整理とサイドパネル枠

表示状態の保存先と所有範囲を整理し、右パネルの開閉・幅・開いているビュー・選択・並び順を統合された状態として保存・復元する。タイトルバー右上に開閉ボタンを追加し、ビューのアイコン切替とドラッグ・キーボードによる並べ替えを実装する。１・２ペイン、狭い幅、別窓での配置と保存競合を確認する。下部パネルや板一覧の開閉状態の統合は対象範囲を区切って進め、利用者設定や保存データを消さない。

### 3. 板一覧とお気に入り

既存の取得・検索・更新通知・お気に入り操作を共有できる境界に整理し、板一覧ツリーとお気に入りビューを接続する。カテゴリ開閉、検索、板・スレを操作中ペインで開く操作、通常ページとの更新同期を確認する。

### 4. スレッド情報を使うビュー

本文の取得・更新を所有するページから、対象タブとページに紐づく読み取り専用スナップショットを共有する。追加取得や古いデータの混入がないことを確認したうえで、次の順に実装する。

- **抽出レス**：入力中の絞り込み、空欄、ハイライト、対象ペインへのジャンプ、状態復元。
- **スレプロパティ**：取得可能な基本情報と既存の勢い・グラフ。欠損情報や過去ログも確認。
- **画像ギャラリー**：タイル、ホバー・フォーカス時の情報、既存ビューア、手動取得設定と大量画像を確認。

### 5. 書き込み欄の表示場所移動

下部・サイド・別窓で既存の書き込みセッションを共有し、編集欄を移動できるようにする。投稿先・下書き・送信状態を保持し、ペイン操作によって投稿先を勝手に変更しない。送信中の移動、二重送信、返信挿入を検証する。

#82 との外枠の役割分担、別 WebView の対応範囲、検索対象や NG との関係などの未確定事項は、該当段階の着手時に確認する。

## 検証

- 単体・統合：ビューの順序・選択・開閉の復元、保存値がない場合の復元、ドラッグとキーボードによる並べ替え、お気に入りの更新同期、対象切替、同じスレの複数ペイン、閉鎖・再表示、更新中の切替、古い非同期結果、検索とハイライト、ジャンプ先、画像取得設定、欠損情報、書き込みの移動と二重送信。
- E2E・実画面：１・２ペイン、縦・横タブ、狭い幅、別窓、キーボード操作、パネル幅変更、表示復元、自動更新中の追従。Chrome・Firefox・Tauri の差を確認する。
- プロジェクト標準の `vp check`、`vp test` と、変更範囲に必要なビルド・E2E を実行する。

## 実装前に決めること

- 板一覧とお気に入りの配置・操作範囲、通常ページとの検索・開閉状態の共有範囲。
- 検索対象の初期値と切替 UI、NG・本文フィルタとの関係。
- パネルを閉じたときの画像取得・ビュー状態の寿命と復元期間。
- 狭い画面・別窓の具体的な配置、プロパティの取得可能項目。
- タイトルバーのオムニバーやメニューを開いている間に別ペインへ切り替えた場合の入力・操作対象。
- 書き込み移動中・送信中の挙動と、左右ペインで同時に書く必要性。
